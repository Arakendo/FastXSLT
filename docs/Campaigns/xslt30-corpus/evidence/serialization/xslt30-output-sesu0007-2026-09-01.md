# XSLT30 unsupported output encoding -- 2026-09-01

## Result

FastXSLT executes the unchanged W3C XSLT30 cases `output-0178`, `output-0180`,
and `output-0185` and reports native serialization error `SESU0007` when XHTML,
XML, or text output requests the unavailable encoding `XXX-xx`. The first two
cases admit that outcome through native error-or-recovery alternatives; the
text case requires the error.

The compiler retains the requested encoding as immutable serialization
metadata. It does not mistake the engine's available serializer lanes for a
static stylesheet-language restriction. The bounded serializer then reports a
structured unsupported outcome carrying the request identity when asked to
materialize an unavailable encoding.

## Boundary conservation

This case does not admit a general encoding implementation. UTF-8 remains the
string lane, and the bounded byte lane continues to own the existing
ISO-8859-1 implementation. An ISO-8859-1 request through the string lane keeps
its private lane-selection diagnostic because FastXSLT can provide those bytes
through the byte result path; other unavailable requested encodings report the
standards-native `SESU0007` from either serialization entry point.

Compilation and semantic transformation remain independent of the eventual
output encoding capability. No filesystem, platform code-page, or ambient host
encoding provider is consulted.

## Denominator movement

This evidence spans two admissions. `output-0185` first moved the complete
output denominator from 76 to 77 passes. Adding `output-0178` and `output-0180`
moves it from 82 to 84 passes and from 150 to 148 visible default not-run cases.
Across the eleven conserved XSLT30 denominators, the current total is 282
passes, with 3 engine unsupported cases, 50 profile exclusions, and 196 visible
default not-run cases.
